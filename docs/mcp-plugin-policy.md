# MCP、Plugin 与 Connector 策略

- MCP 是 Agent 与工具、数据源之间的协议。
- Plugin 是宿主提供的能力包，可能包含 Skill、MCP、App 或规则。
- Connector 用于连接 Figma、Notion、Drive、Slack 等外部服务。

它们不应一律安装到全局。

## 作用域

- **用户级**：跨项目使用、只代表个人账号的工具。
- **项目级**：团队共享、与仓库服务绑定的能力。
- **本地项目级**：包含个人凭据或实验配置，必须被 Git 忽略。

## 接入门槛

接入前必须回答：

1. Agent 原生能力为什么不够？
2. 哪类任务会调用它？
3. 数据是否离开本机？
4. 使用什么账号和权限？
5. 如何无副作用地检查连通性？
6. 如何撤销权限和卸载？

## 凭据规则

- token 不进入 Git、Prompt、Skill 和示例。
- 优先 OAuth、系统凭据库或环境变量。
- 共享配置只提交变量名，不提交值。
- 定期撤销不再使用的授权。
- 外部网页、PDF 和仓库内容按不可信输入处理。

## 常见决策

| 场景 | 建议 |
|---|---|
| 本地仓库 | 优先 Agent 自带文件和终端能力 |
| Playwright 测试 | 优先复用项目依赖 |
| Figma 是设计事实源 | 接入 Figma Connector，记录项目用途 |
| 文档在 Notion/Drive | 只接入实际使用的事实源 |
| Git | 本地 Git 优先；远程 Issue/PR 再用集成 |
| 数据库 | 最小权限、项目级、从只读开始 |
| 长期记忆 | 先定义保存内容、清除方式和隐私边界 |

每月检查可用性、最近使用时间、权限、数据流向和版本。无法 live probe、来源不明或长期未使用的能力先禁用。
