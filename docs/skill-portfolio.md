# Skill 组合与生命周期

## 核心组合

核心 Skill 覆盖软件交付闭环，而不是覆盖所有技术名词：

| 意图 | 建议 Skill | 完成条件 |
|---|---|---|
| 需求与设计 | `think` | 目标、非目标、方案、验收明确 |
| 界面设计 | `ui` | 视觉意图、组件约束和验收明确 |
| Bug 定位 | `hunt` | 找到可验证根因 |
| 审查与发布门禁 | `check` | Findings 或明确残余风险 |
| Agent 环境审计 | `health` | 配置与供应链风险可行动 |
| 调研 | `learn`、`read` | 结论可追溯到来源 |
| 文案 | `write` | 保持原意并符合目标语气 |

语言、框架、OCR、发布平台等专业 Skill 只在真实任务出现时启用。

## 全局还是项目级

与仓库目录、内部脚本、CI 强耦合，或必须由团队共享的流程适合项目级 Skill。通用 Review、Debug 和 Research 适合个人层；项目发布、数据迁移和内部代码生成通常属于项目层。

不要使用固定比例。判断标准是流程的作用域，而不是 Skill 的名称。

## 安装前检查

- 来源和维护者可信。
- 固定到 release、tag 或 commit，而不是盲目跟随 `main`。
- 检查下载脚本、hooks、外部命令和凭据访问。
- 确认没有与已有 Skill 重复。
- 能随时禁用或卸载。

本标准只对白名单中的 `check`、`ui`、`health`、`hunt`、`learn`、`read`、`think`、`write` 提供整组安装建议。Agent 必须先展示来源、完整命令和列表，检查已有冲突并获得明确批准；这不是自动安装权限。当前推荐命令没有显式固定 Waza 版本，执行时应记录实际解析到的来源版本，后续更新仍需单独审查。

## 生命周期

1. **引入**：优先使用清单白名单；清单之外先解决一个真实任务，不按排行榜批量收集。
2. **观察**：记录是否被触发、是否节省时间、是否产生冲突。
3. **固定**：确认有效后固定来源版本。
4. **更新**：一次更新一个来源，阅读 diff，执行代表性任务。
5. **退役**：一个治理周期未使用、被原生能力替代或长期冲突时禁用或删除。

Skill 名称优先描述用户意图，例如 `project-bootstrap`、`release-check`。避免只有 `python`、`react` 这类范围过大的名称；语言规则更适合作为引用资料或路径规则。
