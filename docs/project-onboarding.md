# 新项目接入流程

## 输入要求

一句项目需求应尽量包含要解决的问题、技术栈、主要输入输出、明确非目标和最小验收条件。涉及数据、认证、部署或付费服务时必须询问，不能静默选择。

## 初始化步骤

1. 检查目标目录、Git 状态、已有规则、manifest 和锁文件。
2. 识别已有运行时，不无故引入第二种语言或更换包管理器。
3. 创建最小可用骨架，不提前实现未来扩展。
4. 创建项目 `AGENTS.md`，写入真实命令和边界。
5. 创建一个最小功能与对应测试。
6. 建立一个稳定验证入口。
7. CI 调用相同验证入口。
8. 检查敏感文件忽略规则。
9. 运行验证并报告证据。
10. 等用户授权后再 commit、push 或部署。

## 默认技术选择

默认值用于减少非关键提问，不是强制标准：

- Python CLI：`uv`、`Typer`、`pytest`、`ruff`
- Python Backend：`uv`、`FastAPI`、`pytest`、`ruff`
- Go：标准库优先、`go test ./...`
- Frontend：`pnpm`、`Vite`、按风险选择测试层级

已有项目始终遵循现有栈和锁文件。

## 验收标准

- 新开发者能按 README 启动。
- Agent 能从 `AGENTS.md` 找到正确命令。
- 最小功能和测试通过。
- CI 不依赖个人机器状态。
- 删除项目生成器后，项目仍能独立维护。

同一结构在至少两个真实项目中稳定使用后，才提升为通用模板。
